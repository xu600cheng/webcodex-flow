双枪干活 · 通用流程

桌面端（贵、强）想清楚 → 网页端（便宜、弱一档）搬砖 → 桌面端验收。
最新版：搬运已经压到一行。
一句话：你只搬「一行字」，从不搬代码。
网页端写的代码通过隧道直接写进你本机那个文件夹，改完在编辑器里就能看到。
你要做的全部动作 = 在两边各贴一行指令。
先记住这三行，剩下的都可以忘。
① 派工：读 <项目名>/docs/DISPATCH-001.md，照着做。
② 验收：看 docs/DISPATCH-001.md 这条任务的产出，按 PRD 验收。
③ 续摊：通过后更新 AGENTS.md，并给出下一条任务的派工单和那一行话。

四步循环

步谁干干什么你要手动搬的
1桌面 Codex 澄清需求 → 写 docs/PRD.md、docs/DEV.md、AGENTS.md（任务清单）→ 生成派工单 docs/DISPATCH-00N.md 一行粘贴 ① 到网页端
2网页 ChatGPT 照派工单一次只做一条，代码直写本机；完工把报告写回同一份派工单文件 无代码自动落盘
3桌面 Codex 贴 ②，它自己读文件验收；严重的直接改 一行粘贴 ②
4桌面 Codex 贴 ③，更新清单 → 出下一张派工单 → 回到第 2 步 无跟着第 1 步走

为什么只有一行就够了

以前派工要把「项目路径 + 读哪几份文档 + 做什么 + 规矩 + 验证命令」一整段复制过去。 现在这些全写在派工单文件里，网页端自己读——它本来就能通过隧道读你本机文件。

docs/DISPATCH-001.md  ← 桌面端生成，网页端读，网页端写回完工报告，桌面端验收再读一次
                           ↑ 这三趟往返，你一次都不用搬内容

什么时候退回「整段派工」：任务跨很多文件、上一轮跑偏要额外强调、方案还没定死。 这三种情况让桌面端把整段提示词吐在代码块里。

两条最容易搞混的

① 网页端写的东西会自动落盘吗？
会。它不是在聊天框里吐代码块让你拷——它直接改你本机那个文件夹里的文件。 判断标准：本地文件真的变了才算数，它嘴上说"已写入"而文件夹没动静，就是没动手。 让它报实际调用的工具名（正常能看到 fs_write / fs_apply_patch）。
② 两边看不到对方的聊天记录。
唯一的桥是硬盘上的文件。你在网页端多说了半句要求，桌面端永远不知道—— 所以凡是"要记住的规矩"，必须让它写进文件（PRD / DEV / AGENTS / 派工单）。

三条红线

  1. 方案必须落成文件，对话里说过的话另一边永远看不到
  2. 一次只派一条任务，派一堆只会得到一堆半成品
  3. 动手前让它复述理解，几乎零成本，能挡掉一半返工

开工前检查三件事

  1. 双击「应用程序 / WebCodex.app」——等它弹出浏览器（约 40 秒握手，别提前关）
  2. 网页端必须是「聊天」模式，不是工作区 / Codex 模式
  3. 输入时要用 @WebCodex 或 ➕ 唤出它

换个项目怎么用

改三处即可，以「神笔马良」为例：

地方填什么
面板里的工作区路径/Users/cijiu/Desktop/神笔马良（本机绝对路径）
面板里的工作区名称随便填，自己认得就行（神笔马良）
派工那一行读 神笔马良/docs/DISPATCH-001.md，照着做。（相对路径）

更省事的做法：工作区指向一个「项目大本营」目录，下面每个子目录是一个项目，加一次永久通用。

给桌面端的一次性初始化提示词

新项目发一次，在已经聊了一段的老会话里发效果最好（它熟悉现状）。完整版在仓库 templates/CODEX_INIT_PROMPT.md，核心是这段：

# 要点，不用照抄原文，讲清这五件事即可
1. 我装了 WebCodex，网页 ChatGPT 能直接读写本项目目录
2. 两份额度分开算；分工：你写方案和文档，网页端写代码
3. 方案必须落成 docs/PRD.md、docs/DEV.md、AGENTS.md
4. 每次派工写成 docs/DISPATCH-00N.md，并给我一行「读 xxx/DISPATCH-00N.md，照着做。」
   不要把派工内容整段吐给我
5. 网页端完工报告要写回同一个派工单文件，你验收时自己读，别让我搬

排错

现象怎么办
网页端说"已写入"，本地没变化没真动手。让它报工具名和错误码；确认是聊天模式且用了 @WebCodex
网页端读不到文件WebCodex 没起来，或工作区路径没指向这个目录。回面板核对后重启服务
提示"No space / port occupied"端口被上一个实例占了。双击停止那个 app，再双击启动
启动器打不开（隔离提示）文件被桌面整理工具挪过会带上系统枷锁。xattr -d com.apple.quarantine 解掉
Node 升级后突然启动不了官方脚本写死了 node 路径。已改成运行时自动找，若仍失败重装一次
这套方法已开源：github.com/xu600cheng/webcodex-flow（MIT）
一句实话：网页端模型比桌面端弱一档，所以第 3 步的验收不能省——质量靠流程兜，不靠模型自觉。
