# 派工单（落盘版）

> **用途**：让桌面 Codex 把每次派工的内容写成一个文件，网页端自己来读。
> 这样你在网页端只需要打一行字，不用再复制一整段提示词。

## 怎么用

跟桌面 Codex 说：

```
派第 N 条任务给我，同时把派工单写成 docs/DISPATCH-00N.md。
```

它会做两件事：

1. 在项目里生成 `docs/DISPATCH-00N.md`（内容见下方模板）
2. 给你一行可以直接复制的话：

   ```
   读 <项目名>/docs/DISPATCH-001.md，照着做。
   ```

你在 ChatGPT 网页版（聊天模式 + `@WebCodex`）粘贴这一行就行。
**不用再贴 PRD 路径、不用贴任务描述、不用贴规则**——全在文件里写着。

完工后回桌面端同样可以只打一行：

```
看 docs/DISPATCH-001.md 这条任务的产出，按 PRD 验收。
```

## 什么时候退回「整段派工」

派工单文件适合**常规任务**。
遇到这几种情况，还是让桌面端把整段提示词吐在代码块里，你复制过去：

- 任务跨多个文件、需要临时加约束
- 上一轮网页端跑偏了，要在派工时额外强调
- 任务本身还在讨论，方案没定死

---

## 派工单文件模板（交给桌面 Codex 填）

把下面这段发给桌面 Codex，它会按这个格式产出派工单：

```markdown
# DISPATCH-00N：<任务名>

状态：待执行
派工时间：<日期>

## 一句话目标
<这条任务做完，项目应该变成什么样>

## 上下文（先读这几个文件）
- docs/PRD.md —— 重点看第 <X> 节
- docs/DEV.md —— 重点看 <模块名>
- AGENTS.md —— 任务清单第 <N> 条
- 相关源码：<列出 1-3 个最相关的文件路径>

## 本次范围
改这些文件：
- <路径 1>：<改什么>
- <路径 2>：<改什么>

不要碰：
- 这条任务以外的文件
- node_modules / dist / build / release / .git

## 验收标准
- [ ] <可检查的一条>
- [ ] <可检查的一条>
验证命令：`<命令>`

## 硬约束
1. 动手前先用三句话复述你要改什么、改哪些文件
2. 一次只做这一条，做完停下来报告
3. 不许重构、不许改目录结构、不许新增依赖
4. 验证命令必须真跑，把输出贴出来
5. 卡住就停下来说卡在哪，不许编、不许硬写

## 完工报告格式
做完写回本文件末尾（`## 完工报告` 小节），不要只在对话里说：
- 改了哪些文件
- 验证命令的实际输出
- 有什么没做成 / 偏离了派工单的哪里
```

> 最后一节是整条流程的关键：**让网页端把完工报告写回同一个文件**。
> 这样你回桌面端时连报告都不用搬，让它自己读。
