# 网页端派工提示词模板

两种用法，**日常推荐第一种**（一行搞定），碰到复杂情况再用第二种。

---

## 用法一：一句话派工（推荐）

前提是桌面 Codex 已经把派工单写成了文件（见 [DISPATCH_CARD.md](DISPATCH_CARD.md)）。
你在网页端只需要粘贴这一行：

```
读 <项目名>/docs/DISPATCH-001.md，照着做。
```

项目目录、要读哪些文档、做什么、规矩、验证命令——全在那份文件里，网页端自己读。

**这是整套流程里你唯一需要手动搬运的东西，而且只有一行。**

回桌面端验收同样是一行：

```
看 docs/DISPATCH-001.md 这条任务的产出，按 PRD 验收。
```

---

## 用法二：整段派工（临时加约束时用）

复制到 ChatGPT 网页版（**聊天**模式 + `@WebCodex`）使用。
尖括号里的内容自己填。

```
你接手一个方案已经定好的项目。

项目目录：<项目名，相对路径>
先读 <项目名>/docs/PRD.md、<项目名>/docs/DEV.md、<项目名>/AGENTS.md 三份文件。

本次只做第 <N> 条任务：<任务名>。
不要碰这条任务以外的文件。
不要读取 node_modules / dist / build / release / .git。

规则：
1. 先用三句话复述你理解的任务和要改的文件，然后再动手
2. 一次只做这一条，做完停下来报告
3. 不许重构、不许改目录结构、不许新增依赖
4. 改完跑一遍 <验证命令>，把结果贴给我
5. 卡住就停下来说卡在哪，不许编、不许硬写

现在开始。
```

## 判断它到底干没干活

- ✅ **真的通了**：本地文件夹里出现文件变化
- ❌ **假的**：它说"已写入"但文件夹没变化 → 让它报**实际调用的工具名和错误码**
  （正常会看到 `fs_write` / `fs_apply_patch`）。没有工具调用记录就是它根本没动手
